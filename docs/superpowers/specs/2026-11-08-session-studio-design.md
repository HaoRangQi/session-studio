# Session Studio 产品与技术设计

> 状态：已由用户逐节确认（2026-11-08）
> 范围：单机 macOS 桌面应用；本文件是产品与架构权威来源。实施计划见 [实施计划](../plans/2026-11-08-session-studio.md)。

## 目标

构建 Session Studio：统一管理本机 Claude Code、Codex、DeepSeek Harness、Pi 的 agent 会话资产，并以清理、导出、按需 AI 分析和活动任务监控降低会话散落与资源归属不清的问题。首发要求四个来源各自通过真实会话样本闭环验收；未通过真实验证的能力不得标为完成。

## 产品范围

- macOS 桌面应用，使用 Tauri 2；界面先以功能可用为主，后续可专项设计。
- 本地元数据索引与任务历史，不提供账户、云端会话库或跨设备同步。
- 首次启动及来源设置显示 Claude Code、Codex、DeepSeek Harness、Pi 各自的默认会话目录和扫描状态；默认目录可直接点击扫描，不要求先手动选择目录。
- 默认目录以当前用户 home 与工具官方环境变量规则解析：Claude Code 为 `CLAUDE_CONFIG_DIR`（默认 `~/.claude`）下的 `projects/`；Codex 为 `CODEX_HOME`（默认 `~/.codex`），扫描其 `sessions/` 与 `archived_sessions/`；DeepSeek Harness 为 `DSH_HOME`（默认 `~/.dsh`）下的 `sessions/`；Pi 为 `PI_CODING_AGENT_DIR`（默认 `~/.pi/agent`）下的 `sessions/`。
- 用户可以逐来源选择自定义目录，也可以恢复工具默认目录。仅扫描明确展示的来源目录；不扫描无关隐藏目录、系统目录、其他卷或整个主目录。
- 显示默认路径本身不访问文件。只有用户明确点击扫描时才读取该来源；路径不存在、格式待验证、读取失败和系统拒绝访问必须分开显示，不能伪装成“未授权”或空扫描。
- 不请求整个主目录或 Full Disk Access；若 macOS 在用户启动的扫描过程中确实拒绝读取，报告实际权限错误，不将手动选目录设为常规前置条件。
- 列表同时支持全局会话视图与项目聚合视图，固定侧边栏入口为“全部会话、项目、清理候选、活动任务”。
- 会话正文不进入默认索引；打开详情、导出或 AI 分析时按需解析。
- 会话来源：Claude Code CLI、Codex CLI、DeepSeek Harness、Pi。它们分别通过独立适配器对接，格式差异不得泄漏进共享领域模型。
- 上游格式依据：Codex `CODEX_HOME/sessions` 与 `archived_sessions`、rollout 文件名/压缩实现见 [Codex rollout 源码](https://github.com/openai/codex/tree/main/codex-rs/rollout/src)；Pi 会话目录、版本头和 JSONL 事件见 [Pi session format](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/session-format.md) 与 [sessions guide](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/sessions.md)；DeepSeek Harness 的 JSONL root、版本日志与压缩见 [DSH session persistence](https://github.com/deepseek-ai/deepseek-harness/tree/main/packages/session/session-persistence-jsonl) 和 [home path rules](https://github.com/deepseek-ai/deepseek-harness/tree/main/packages/util/home-paths)。这些链接描述上游当前格式，不替代真实本机样本验收。Claude Code 会话路径/格式暂用可配置候选；尚未找到稳定公开格式契约。
- 清理候选原因：项目路径不存在、未关联项目、超过 90 天未活动。重复检测不在首发范围。权限不足或路径不可访问标为无法确认，不能推断为孤儿。
- 导出支持 Markdown 与 JSON；默认包括完整消息、工具调用/输出、时间和来源元数据，附件只保留引用，不复制二进制内容。支持批量导出多条会话。
- AI 处理支持多会话合并成一个任务；用户选择每条会话的整条内容或消息范围并提供自定义指令。
- AI 任务通过所选工具的 CLI 启动独立会话，优先使用无历史/临时模式，保持原始会话只读。
- 复用所选 CLI 当前模型/后端配置，不在应用内另存模型凭证。未知后端按可能远程处理，每次预览风险并确认。
- AI 执行默认要求只读；如果 CLI 无法保证只读，则明确警告，用户额外确认后可继续。远程发送不自动脱敏，提示用户自行审阅。
- AI 任务结果、失败原因和部分输出保留于本机，直到用户主动清理；不自动写入项目目录或自动导出。用户在每次完成后选择保存位置。只允许取消 Session Studio 自己启动的分析任务。
- 活动任务只监控四种受支持 CLI 及其子进程，显示 agent、工作目录、进程启动时间/运行时长和状态；不读取正文，不显示 CPU、内存、Token、费用，不暂停/终止外部任务。
- 若待清理容器关联到活动进程，或活动关联无法可靠判断，则禁止清理。
- 本地元数据索引持久化保存，可清空并重建。AI 任务记录与索引分开管理。
- 来源状态显示已发现、未安装、权限不足、格式不支持、扫描失败、扫描成功但无会话及最近扫描时间。状态中心位于设置页；筛选和结果列表使用简要状态徽标。
- 扫描为按需执行：打开来源/列表或手动刷新时更新元数据。活动任务状态只在监控页打开期间轻量刷新。

## 关键操作流程

### 首次发现

1. 展示四种来源总览、解析后的默认会话目录及当前扫描状态，不弹出目录选择或权限请求。
2. 用户可直接点击扫描默认目录，或先选择自定义目录；显示路径本身不访问其内容。
3. 适配器只在用户点击扫描后读取选定目录，并将可访问容器的元数据写入 SQLite。
4. 将目录不存在、系统权限拒绝、格式待验证/不支持、扫描失败与成功但无会话分别展示；失败不覆盖成空结果。

### 容器级批量清理

1. 用户可从全局列表、项目视图或清理候选多选会话。
2. 将所选会话映射到实际存储容器并去重。
3. 每个容器重新检查路径、来源状态和活动进程关联。
4. 预览显示路径、容器中会话数、预计影响、可清理/阻止状态及理由。
5. 活动关联明确或不确定的容器禁用清理；其他容器可继续。
6. 用户确认后，将可清理容器移入 macOS 垃圾篓。批次允许部分成功，结果逐项显示；任何操作都不执行永久删除。

### 导出

1. 用户选择一条或多条会话。
2. 适配器按需解析源容器，并产生 Markdown 或 JSON；同容器中的其他会话不会被误认为导出目标。
3. 附件仅序列化引用，不复制文件。
4. 用户选择保存位置；记录逐项成功/失败。

### AI 分析

1. 选择一个适配器/CLI、多个会话、自定义指令及每个会话的消息范围。
2. 显示当前 CLI 能检测到的模型/后端；无法判断时标记未知并按可能远程处理。
3. 生成并展示实际提交内容，含完整选定消息、工具事件和指令；提示不自动脱敏。
4. 远程或后端未知时逐次确认数据外发。CLI 不能保证只读时显示风险并额外确认。
5. 优先启用 CLI 无历史/临时模式；不支持时提示将新增独立会话并征求确认。
6. 启动隔离 CLI 进程，支持取消本应用任务，记录退出码、错误和完整/部分输出。
7. 结果保留在本地任务库，用户选择是否以及保存到何处；不得改写源会话或自动写项目文件。

## 架构

### 技术基线

- Tauri 2 桌面壳，Rust 后端。
- React、TypeScript、Vite 前端，首发不引入重量级 UI 组件库。
- SQLite 保存会话元数据索引、来源扫描状态、用户标签/归组和 AI 任务记录；不保存原始会话正文副本。
- 四种来源优先使用工具默认目录；选择自定义目录是可选操作。只有用户点击扫描后才读取所示来源路径；若 macOS/Tauri 实际拒绝访问，显示具体权限错误，不把手动选目录当作常规授权前置条件。垃圾篓使用系统 API。具体 Tauri 插件/API 必须在实现阶段查证并测试。

### 领域边界

- `SessionProvider`：单个来源的目录发现、元数据扫描、消息解析、原生容器映射和能力声明。
- `ActivityProvider`：对相应 CLI 的进程/子进程发现、工作目录和启动时间检测。
- `CliRunner`：安全启动指定 CLI，构建只读/无历史参数，流式收集输出并支持取消；不能静默放开 CLI 的权限。
- `SessionRepository`：通过统一 DTO 暴露索引查询、双视图、筛选和来源状态。
- `CleanupService`：容器去重、活动关联复查、预览、垃圾篓移动和逐项结果。
- `ExportService`：将适配器规范化消息序列化为 Markdown/JSON。
- `AnalysisService`：范围选择、实际输入预览、数据外发与 CLI 风险确认、任务生命周期及输出保存。
- React UI 只调用有类型定义的 Tauri commands/events，不直接读取本地文件。

### 统一数据模型

统一 DTO 至少包括：来源类型、来源稳定 ID、会话标题/时间/工作目录、来源容器路径、容器标识、消息数、最近修改时间、解析能力/状态、活动状态（running / inactive / unknown）、清理候选标签及扫描错误。消息类型保留 role、时间、文本/结构化工具调用、工具结果和附件引用。不同来源的原始字段可作为按需解析的适配器数据，不进入跨来源的必要字段。

### 安全与数据保护

- 全部应用数据库与 AI 输出只存本机应用数据目录，依赖 macOS 用户账户权限及 FileVault；不另行实现应用层加密。
- 不记录 API 密钥、凭证、原始会话正文到诊断日志。
- 路径访问失败与容器身份不确定时采取保守行为；不猜测格式，不执行危险清理。
- AI CLI 启动参数使用固定参数数组而非 shell 拼接；限制工作目录、权限配置与环境变量继承，避免命令注入及意外读写。
- AI/远程数据发送必须在每次任务前预览实际内容并确认；用户承担未自动脱敏风险。
- 文件系统操作要处理源文件变化、容器锁定、垃圾篓 API 失败、磁盘不可用和部分批量失败；失败项保留原样并展示原因。

## 验收与测试

- 纯 Rust 单元测试覆盖统一 DTO、标签判断、容器去重、消息范围规范化、导出编码与失败分类。
- 每个适配器用固定脱敏样本测试：元数据提取、正文解析、工具调用/结果、附件引用、项目路径与容器映射；未知/损坏格式必须显式失败。
- SQLite 集成测试覆盖增量更新、删除失效索引、状态保留、清空重建和模式迁移。
- macOS 集成测试覆盖用户点击扫描后的来源目录访问、测试文件夹垃圾篓移动与恢复、活动进程关联保护、CLI 输出流/退出码/取消。
- AI CLI 测试仅使用无副作用模拟可执行文件，不调用真实模型、不产生费用；验证参数数组、隔离配置、临时会话优先、失败/取消部分输出保存和输入预览一致性。
- 前端测试覆盖固定侧栏、全局/项目双视图、默认目录展示、直接扫描、自定义路径恢复、来源状态、清理预览和逐项结果。
- 发布验收要求四种来源分别用真实会话样本完成发现、浏览、Markdown/JSON 导出、垃圾篓清理及 CLI 分析闭环；用户需在本机提供可访问样本和所需 CLI。当前 `dsh` 命令缺失，故 DeepSeek Harness 真实闭环目前阻塞，不能标记为已完成。
- 实际格式、数据目录、CLI 隔离参数和垃圾篓系统调用均须有运行时证据；不得以猜测替代。

## 明确不做

- 不做云同步、账户系统、跨设备数据服务。
- 不管理或控制用户从应用外启动的 agent 任务。
- 不做重复/语义相似检测、CPU/内存/Token/费用仪表盘。
- 不做自动脱敏、自动永久删除、自动写回项目、自动保存 AI 结果到会话来源。
- 不复制附件二进制数据，不默认全文索引或缓存会话正文。
- 不默认支持 Claude Desktop；“Claude”在本设计中指 Claude Code CLI。

## 待核实与阻塞

- DeepSeek Harness 官方 CLI 名称为 `dsh`，npm 入口为 `@deepseek-ai/dsh`；CLI 配置层通过 `DSH_HOME`（默认 `~/.dsh`）解析 `sessions/` root。JSONL persistence API 本身要求传入 root，CLI 提供默认配置；日志使用版本化 JSONL 并默认 Zstandard 压缩。当前环境未安装该 CLI，实际本机样本、压缩版本解码及真实会话闭环仍待验证。
- Claude Code、Codex、DeepSeek Harness、Pi 的默认候选目录及环境变量覆盖规则已核实；真实本机数据格式、压缩变体、版本兼容与真实会话闭环仍需在适配器任务中验证。
- 当前环境没有完整 Xcode，仅有 Command Line Tools；Tauri macOS GUI 打包/运行可能受阻，需安装完整 Xcode 才能完成最终桌面验收。
- 官网签名/公证和 App Store 分发暂不纳入内测首发。
